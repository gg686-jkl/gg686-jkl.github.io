**（部分内容由与AI讨论得出）**

我最初提出 OEC，Open-Ended Cognition，不是为了做 XAI，也不是为了做一个 mindmap 工具。

它源于一个问题：

> chatbot 的线性对话形式，不适合长期、复杂、可回溯的认知工作。

传统 chatbot 以 message 为基本单位。它适合即时问答，但不适合持续研究。对话越长，信息越难回看，上下文越容易污染，结论也越难沉淀。很多有价值的推理最后都被埋在聊天记录里，无法复用、修正和扩展。

OEC 的基本想法是：把 AI 交互的最小单位从 message 改成 node。

每个 node 是一个独立认知单元，可以存储概念、问题、假设、证据、推导、反例或实验结果。节点之间用 DAG 连接，表示前提、推导、中介、冲突等关系。

这意味着，AI 交互不再是：

```text
message → message → message
```

而是：

```text
前提节点 → 当前节点 → 推导节点
        ↘        ↘
        中介节点   冲突节点
```

OEC 的核心变化不是“把聊天画成图”，而是把认知上下文从时间顺序改成结构关系。

在 chatbot 里，系统通常根据最近的对话内容决定上下文。
在 OEC 里，系统应该根据当前节点的相邻关系决定上下文。

这使 AI 交互从 conversation-centric 变成 node-centric。

---

## 1. OEC 的四个操作

OEC 的核心操作后来被整理为四个：

```text
Ground
Derive
Reconcile
Mediate
```

它们不是普通功能按钮，而是四种认知变换。

---

### Ground：寻找上游前提

Ground 解决的问题是：

> 理解当前节点，需要哪些前提？

在普通知识场景里，它生成背景知识。
在机制解释场景里，它对应：

> 当前行为或机制由哪些上游组件导致？

例如：

```text
Behavior: IOI logit_diff
Ground →
可能相关的 upstream heads / features / components
```

Ground 的本质是上游搜索。

---

### Derive：推导下游影响

Derive 解决的问题是：

> 如果当前节点成立，它会产生哪些下游影响？

在机制解释场景里，它对应：

> 一个组件会影响哪些 logit、行为、路径或下游组件？

例如：

```text
Component: L8H6
Derive →
correct_name logit
wrong_name logit
IOI logit_diff
downstream mediator candidates
```

Derive 的本质是下游效应追踪。

---

### Reconcile：局部自洽修正

Reconcile 解决的问题是：

> 当新证据出现后，当前节点如何与相邻节点重新自洽？

它不是 reset，也不是简单重写。
它更接近局部信念修正。

例如：

```text
旧命题：
L8H6 contributes to IOI.

新证据：
L9H9 partially mediates L8H6 → IOI.

Reconcile 后：
保留 L8H6 contributes to IOI，
同时新增：
L9H9 partially mediates this effect，
以及 residual direct effect。
```

这说明 Reconcile 不应该简单替代旧命题，而应该在证据支持下细化旧命题。

---

### Mediate：寻找中介机制

Mediate 来自 OEC 早期的 bridge 思想。

普通 bridge 可能只是联想。
但在 OEC-MEG 里，Mediate 必须变成可验证的中介假设：

```text
A → M → B
```

其中：

```text
A = upstream component
M = mediator candidate
B = behavior
```

Mediate 的目标不是“把两个节点连起来”，而是提出一个可干预、可证伪的机制路径。

这是 OEC-MEG 目前最重要的实验突破口。

---

## 2. 从 OEC 到 OEC-MEG

OEC 最初是 AI 交互架构。

(也将他成功应用做成一个开源项目Ymind:https://github.com/gg686-jkl/Ymind)

但它天然引出了一个更难的问题：

> OEC 能不能不仅组织用户认知，也组织 AI 内部机制解释？

这就是 OEC-MEG 的起点。

MEG 是 Mechanistic Evidence Graph，机制证据图。

但这里必须谨慎：OEC-MEG 不是底层解释算法。它不替代 linear probe、activation patching、SAE、transcoder、attribution graph、circuit tracing 或参数分解。

更准确的定位是：

> OEC-MEG 是一种机制解释证据的组织、修正、版本化和验证运行时。

OEC-MEG 的目标不是直接“解释模型”，而是让机制解释研究过程变得结构化、可回溯、可证伪。

---

## 3. 从 claim 到 typed mechanism proposition

OEC-MEG 不能把节点写成普通自然语言 claim。

例如：

```text
L9H9 是 IOI 的中介机制。
```

这不够严谨。它只是一个解释性说法。

在 OEC-MEG 里，这类内容必须变成 typed mechanism proposition：

```text
proposition_type = partial_mediation
A = component_L8H6
M = component_L9H9
B = behavior_IOI_logit_diff
scope = GPT-2 small / IOI / distractor split / hook_z
test_protocol = path-specific activation patching
criteria = mediation_fraction CI lower bound > random control 95pct
evidence_refs = concrete patching / mediation evidence objects
truth_status = supported_preliminary 或 supported_replicated
```

自然语言只能作为 `verbal_summary`，不能作为科学对象。

这个转变很关键：

```text
解释文本
↓
可检验机制命题
```

也就是说，OEC-MEG 不是 explanation graph，而应该是 graph of testable mechanism propositions。

---

## 4. 实验目标：不要一开始证明整个 OEC-MEG

OEC-MEG 的完整目标很大。直接证明它能解释大模型并不现实。

所以第一阶段实验被压缩成一个小问题：

> OEC 的某个操作能否被转化为机制可解释性实验，并产生可证伪结果？

实验对象选择：

```text
模型：GPT-2 small
任务：IOI-style prompts
工具：TransformerLens + activation patching
核心行为：IOI logit_diff
```

IOI 是 Indirect Object Identification，是 mechanistic interpretability 中常用的小任务，适合做第一轮实验。

---

## 5. v0.1：跑通实验管线

v0.1 的目标是工程可行性。

它完成了：

```text
生成 IOI prompt pairs
运行 GPT-2 small
做 activation patching
计算 component effect size
生成 evidence objects
构建 nodes / edges
输出 report
```

v0.1 的结果：

```text
工程管线：通过
Reconcile：没有提升 held-out MAE
Mediate：仍是 observational candidate
```

所以 v0.1 没有证明 OEC-MEG 成立。
它只证明实验路线可以跑。

---

## 6. v0.2：Mediate 进入因果验证

v0.2 加入了更强的科学保护：

```text
paired bootstrap
coverage / abstention metrics
negative controls
path-specific interventional mediation test
```

Mediate 被形式化为：

```text
A = L8H6
M = L9H9
B = IOI logit_diff
```

测量：

```text
TE = patch A 的总效应
DE = patch A 但 block M 后的直接效应
IE = TE - DE
mediation_fraction = IE / TE
```

这个实验把 OEC 的 bridge 操作转化成了 causal mediation hypothesis。

v0.2 的结果：

```text
L9H9 作为指定 mediator，有初步正向信号。
它强于 random control 和 low-effect control。
```

但限制也很明显：

```text
只验证了指定 mediator。
没有证明系统能自动发现 mediator。
Reconcile 仍没有稳定价值。
```

因此 v0.2 的结论是：

> Mediate verification 有潜力，但 Mediate discovery 还没有解决。

---

## 7. v0.3：Mediate 信号复现，Reconcile 图重写失败

v0.3 的目标是复现 Mediate 信号，并尝试让 Reconcile 利用 Mediate 结果改写图结构。

它加入了：

```text
多 seed
多 random controls
bootstrap CI
top-k candidate verification
Reconcile-Mediate rewrite
rollback
```

v0.3 的关键结果：

```text
L9H9 的 mediation signal 在多个 seed 上继续稳定。
```

这说明 L9H9 不是一次偶然结果。

但 Reconcile-Mediate rewrite 失败了。
原因是它仍试图把机制证据变成可组合的边权图，例如用路径权重预测 TE / DE / IE。实际模型中的 patching effect 并不满足这种简单线性组合假设。

因此 v0.3 的结论是：

```text
Mediate verification：有信号。
Reconcile graph rewrite：失败。
```

这个结果很重要。它说明 OEC-MEG 不是整体成功，也不是整体失败。不同操作必须分别验证。

---

## 8. v0.4：引入 Proposition Layer

v0.3 后，一个问题变得明显：

> 如果 OEC-MEG 的 claim 仍是自然语言，它就不够科学。

因此 v0.4 引入 `MechanismProposition`。

每个机制命题必须包含：

```text
proposition_type
formal
scope
test_protocol
criteria
evidence_refs
evidence_summary
truth_status
verbal_summary
```

这一步把 OEC-MEG 从普通图解释推进到机制命题系统。

v0.4 的结果：

```text
Proposition Layer：工程上成功
Mediate 证据：可以被形式化表达
Reconcile-as-replacement：失败
```

失败原因也清楚：

```text
partial_mediation 不应该替代 direct_contribution。
```

如果 A 对 B 有总效应，而 M 中介了其中一部分，那么正确表达应该是：

```text
A contributes to B.
M partially mediates A → B.
A still has residual direct effect on B.
```

所以 partial mediation 是 refinement，不是 replacement。

---

## 9. v0.4.5：Reconcile 从 replacement 改为 refinement

v0.4.5 修正了这个概念错误。

新的结构是：

```text
Parent:
direct_contribution(A, B)

Children:
partial_mediation(A, M, B)
residual_direct_effect(A, B | blocked_mediator = M)

Revision:
refinement(parent → children)
```

这更接近 OEC 的原始精神：

> 旧节点不一定被删除，而是在新证据出现后长出更细的局部结构。

v0.4.5 也修正了 evidence coverage 指标，将其拆成：

```text
proposition_local_evidence_coverage
global_evidence_object_coverage
```

这避免了把 inactive components 的未引用 evidence 错误解释为 proposition 证据不足。

---

## 10. v0.4.5-complete：关键负结果

v0.4.5-complete 做了一件重要的事：

> 不再只验证 L9H9，而是尝试真正做 Mediate Explorer。

候选池扩展为：

```text
layers 7-11 的所有 attention heads
排除 upstream A = L8H6
约 59 个候选 head
```

流程是：

```text
discovery split 上排序候选
held-out distractor split 上验证 top-k candidates
```

结果是负面的：

```text
没有发现 robust mediator family。
L9H9 没有稳定进入 top-k。
top candidates 在 held-out 上多为 suppressor 或 null。
Reconcile-as-Refinement 没有成功产生 child propositions。
```

这说明一个关键事实：

> OEC-MEG 目前不是不能验证 mediator，而是不能稳定发现 mediator。

如果手动指定 L9H9，系统能验证它有中介信号。
但如果让系统从大量 heads 中自动找 mediator，当前 discovery score 找不到 L9H9，也找不到稳定 mediator family。

因此，v0.4.5-complete 的真实结论是：

```text
Mediate verification：有希望。
Mediate discovery：失败。
Reconcile refinement：依赖 mediator discovery，因此未闭环。
```

---

## 11. 当前瓶颈：Discovery 不等于 Verification

这是目前最重要的教训。

Mediate verification 问的是：

> 给定 A、M、B，M 是否在 A → B 中承担中介作用？

Mediate discovery 问的是：

> 在大量候选 M 中，如何找到值得验证的 M？

这两个问题不同。

当前使用过的 discovery score 类似：

```text
discovery_score = mse_A - mse_AM
```

它衡量的是加入候选 M 后预测误差是否下降。

但实验结果说明：

> 预测能力提升不等于因果中介作用。

一个 head 可以携带和行为相关的信息，也可以帮助预测输出，但这不代表模型通过它传递 A → B 的因果效应。

这就是当前 OEC-MEG 的核心瓶颈：

```text
interventional verification 可以工作；
candidate discovery 还不可靠。
```

---

## 12. 下一步：v0.4.6-pre，Mediate Discovery Calibration

因此，下一步不应该扩展到 SAE、VPD、MLP、residual stream 或前端。

最合理的小版本是：

```text
v0.4.6-pre:
Mediate Discovery Calibration
```

目标不是发现新 mediator，而是先回答：

> 哪种 discovery score 能把已知正例 L9H9 排进 top-k？

这一步把 L9H9 当作 calibration target。

要比较多种 discovery score：

```text
S1: 当前 regression score = mse_A - mse_AM
S2: activation correlation score
S3: attribution patching score
S4: edge attribution / EAP score
S5: cheap path patching score
S6: hybrid score
```

关键输出：

```text
L9H9 rank
L9H9 是否进入 top-5
top-5 candidates 的 held-out mediation performance
discovery score 与 held-out mediation fraction 的相关性
```

成功标准：

```text
至少一种 score 能让 L9H9 在 2/3 seeds 中进入 top-5。
top-k candidates 在 held-out verification 中优于 random controls。
```

如果没有 score 能找回 L9H9，就说明 OEC-MEG 目前还没有可用的 Mediate discovery 方法。

---

## 13. 当前 OEC-MEG 的真实状态

截至目前，比较准确的状态是：

```text
已经成立：
- OEC-MEG 可以被实现为实验管线。
- Evidence objects 可以被结构化记录。
- Natural-language claim 可以升级为 typed mechanism proposition。
- Mediate verification 可以用 TE / DE / IE 做因果中介测试。
- 指定 L9H9 时，出现过稳定的正向 mediation signal。
- Reconcile-as-refinement 比 replacement 更合理。
- Active propositions 可以做到 local evidence coverage。

尚未成立：
- 系统不能自动稳定发现 mediator。
- 当前 discovery score 找不回 L9H9。
- mediator family exploration 未成功。
- Reconcile 还没有成功生成可靠 refinement。
- OEC-MEG 整体不能称为科学验证成功。
```

这不是坏结果。
它说明项目已经从概念阶段进入了实验阶段。

实验已经不是在问：

```text
OEC-MEG 听起来是否合理？
```

而是在问：

```text
哪个操作能被验证？
哪个操作失败？
失败发生在哪个环节？
下一步该校准什么？
```

这才是有效研究。

## 14. 重新理解四个操作的实验状态

现在四个操作的状态可以这样看：

```text
Ground：
可以作为 upstream component search 使用，
但还没有独立验证其科学价值。

Derive：
已经用于 component effect tracing，
但还没有形成完整 downstream proposition mapping。

Mediate：
作为指定 mediator 的因果验证，有正信号。
作为自动 mediator discovery，目前失败。

Reconcile：
作为 confidence/scope update 失败。
作为 graph rewrite 失败。
作为 proposition replacement 失败。
作为 proposition refinement 更合理，但依赖可靠 mediator discovery，目前未闭环。
```

所以 OEC 的四个操作不是一起成功或一起失败。
它们需要分别形式化、分别实验、分别评估。

---

## 15. OEC-MEG 的当前定位

我现在对 OEC-MEG 的定位更保守：

> OEC-MEG 不是直接自动解释模型的系统，而是机制解释研究的结构化运行时。

它管理的不是 AI 编出来的解释文本，而是：

```text
机制命题
证据对象
干预协议
冲突结果
命题修正
失败路径
候选发现方法
验证结果
```

它的价值不一定在于“一键解释模型”，而在于让机制解释研究过程变得：

```text
结构化
可回溯
可证伪
可修正
```

这也是目前实验最支持的方向。

---

## 16. 这条路线还值得继续吗？

我认为值得。

不是因为 OEC-MEG 已经成功，而是因为它已经产生了有效的正负结果。

目前最重要的结果不是：

```text
OEC-MEG works.
```

而是：

```text
Mediate verification 有信号。
Mediate discovery 失败。
Reconcile 依赖 discovery，因此暂时无法闭环。
下一步应该做 Mediate Discovery Calibration。
```

这比一个笼统的“成功”更有价值。

一个研究路线是否值得继续，不取决于每一步是否成功，而取决于失败是否能缩小未知空间。

v0.4.5-complete 已经把问题缩小到一个清晰点：

> 如何发现真正的 mediator？

这就是下一步的靶心。

---

## 17. 总结

OEC 最初试图解决 chatbot 的线性交互限制。
它把 AI 交互从 message flow 改造成 node graph。

OEC-MEG 是更进一步的尝试：

> 能否把开放式认知图，转化为机制可解释性中的证据图和命题系统？

目前答案是：

```text
可以部分转化，但不能简单转化。
```

最有希望的部分是 Mediate：

> bridge 可以被严格化为 causal mediation hypothesis。

当前最大的困难也是 Mediate：

> 系统还不能稳定发现 mediator。

Reconcile 的未来依赖这个问题。只有当系统能发现可靠 mediator，Reconcile 才能把粗命题细化成更好的机制结构。

所以当前阶段性结论是：

> OEC-MEG 已经从概念架构进入可证伪实验阶段；它还没有证明自己是完整的 XAI 基础架构，但已经证明自己可以作为机制解释研究的结构化运行时，并暴露了一个清晰的核心难点：Mediate Discovery Calibration。

这不是终点。

但它比“概念上看起来合理”重要得多。

因为从这里开始，OEC-MEG 不再只是一个想法。
它已经开始被实验反驳、修正和推进。
